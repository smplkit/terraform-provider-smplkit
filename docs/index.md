# smplkit Provider

The smplkit provider manages resources on the [smplkit](https://smplkit.com)
platform — configurations, feature flags, audit forwarders, log groups,
environments, and services — through the smplkit management API.

The provider is a thin wrapper over the public [Go SDK](https://github.com/smplkit/go-sdk)'s
**management client**. It performs CRUD against the documented public API; it does
not auto-register services, emit metrics, open a live-update stream, or carry any of
the discovery side-effects the runtime SDK clients have.

## Authentication

The provider authenticates with a smplkit API key. Create one in the smplkit
console under **Settings → API keys** (the account must have a verified email).

Configure the key in one of three ways, in precedence order:

1. The `api_key` argument on the provider block (least preferred — avoid
   committing keys to version control).
2. The `SMPLKIT_API_KEY` environment variable (preferred for CI).
3. A `~/.smplkit` profile file managed by the smplkit CLI (preferred for
   local development).

## Getting started

```terraform
terraform {
  required_providers {
    smplkit = {
      source  = "smplkit/smplkit"
      version = "~> 1.0"
    }
  }
}

# The provider reads SMPLKIT_API_KEY from the environment by default.
# Set api_url to talk to the local platform (ADR-042) instead of production.
provider "smplkit" {
  # api_key = "sk_api_..."          # or set SMPLKIT_API_KEY in the environment
  # api_url = "http://localhost"    # local platform via the Caddy proxy
}

# A minimal first example — declare a service and a configuration that
# inherits the service's id as its key. Both id and name are required.
resource "smplkit_service" "user_service" {
  id   = "user_service"
  name = "User Service"
}

resource "smplkit_configuration" "user_service_config" {
  id   = smplkit_service.user_service.id
  name = "User Service Config"

  items = {
    cache_ttl_seconds = jsonencode(300)
    feature_x         = jsonencode(true)
  }
}
```

## Resource identity and updates

Every resource uses a **caller-supplied `id`**: a stable, human-readable
string that the platform also surfaces in console URLs. The same `id` is
the import identifier, so `terraform import smplkit_flag.dark_mode dark_mode`
adopts an existing flag by key with no UUID lookup.

Updates use full-replace semantics — when Terraform applies a change it
sends the entire resource representation. Per-environment overrides,
targeting rules, and nested attributes are part of that representation,
so a single apply replaces all of them atomically.
